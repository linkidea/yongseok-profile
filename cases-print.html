CASE 01 · 리스크·감사

리스크를 개인의 경험이 아니라,
전사의 언어로

각 부서의 사후 대응을 전사 리스크 맵과 상시 모니터링으로 바꾼 3개월

01배경 — 문제

리스크 관리가 각 부서의 경험과 사후 대응에 머물러 있었습니다.

  • 부서별 관리 — 리스크를 각 부서가 개별적으로 관리, 공통 기준과 언어 부재
  • 사후 대응 — 문제가 발생한 뒤에야 확인·조치, 예방보다 수습 중심
  • 경험 의존 — 담당자의 경험과 판단에 따라 관리 수준이 달라짐
  • 계기 — 반복되는 사고와 진단 결과가 전사 차원의 기준·모니터링 필요성을 드러냄

02접근 — 어떻게

  • 리스크 맵 — 11개 Core-Work별 리스크 요소 118개를 정의하고, 사업별 리스크 맵으로 정리했습니다.
  • 생애주기 — 식별→평가→대응→모니터링→종료 템플릿을 만들고, 분기 1회 리뷰를 운영했습니다.
  • 진단 연결 — 리스크 맵을 진단 계획·우선순위에 반영해, 진단 대상 선정과 구매관리 규정 개정으로 연결했습니다.
  • 이상징후 — 매출 비중·매입처 신용도·거래액 변동·신규 거래처·집중도·OB거래 등을 임계값 기반으로 점검했습니다. AI를 활용해 로직을 개발했고, 이상 수치가 나오면 각 사업부에 사유를 확인하고 조치를 요청했습니다.

03결과 — 숫자로

11개 Core-Work · 리스크 관리 단위
118개 리스크 요소 · 사업별 리스크 맵
7개 사업부·자회사 · 분기 1회 리뷰

04이 사례가 보여주는 것

  • 예방형 감사의 본질 — 적발이 아니라, 리스크를 미리 정의하고 상시 신호로 바꾸는 것입니다.
  • 현업 출신 감사의 강점 — 진단 결과를 구조로 바꾸고, 사업부와 기준을 합의해 운영하는 것입니다.
  • 실행력 — 데이터 접근 제약과 기준 합의의 난이도를 3개월 안에 풀어냈습니다.

CASE 02 · 감사·윤리

한 건의 감사가,
전사에 남는 방식

비위·윤리 사고 사례를 분석해 원인과 징후를 정리하고, 공지문과 동영상으로 사업부에 공유

01배경 — 문제

감사가 개별 사건의 적발로 끝나면, 같은 유형의 비위가 다른 사업부에서 반복됩니다.

  • 적발 중심 — 사건을 확인하고 종결하는 데 그치면, 원인과 징후가 조직에 남지 않음
  • 사례 미공유 — 같은 유형의 리스크가 다른 사업부에서 다시 발생
  • 현장 언어 부재 — 감사 보고서는 현장이 읽기 어려워 예방으로 이어지기 어려움

02접근 — 어떻게

  • 분석 범위 — 횡령·리베이트·이해충돌·허위청구·법인카드 부정사용 등
  • 분석 프레임 — Fraud Diamond(기회·압박·합리화·능력)로 원인을 구조화
  • 공지 콘텐츠 — 공지문과 동영상, 현장이 이해할 수 있는 언어로
  • 진단 연결 — 진단에서 발견한 징후를 사례 분석으로 확인하고, 다시 공지로 환류

03결과 — 숫자로

5개 비위 유형 · 횡령·리베이트·이해충돌·허위청구·법인카드
2종 공지 콘텐츠 · 공지문·동영상
7개 사업부·자회사 공지

04이 사례가 보여주는 것

  • 감사의 목적은 적발이 아니라 재발 방지 — 사건을 넘어 원인과 징후를 남깁니다.
  • 사례 공지는 경고가 아니라 학습 — 같은 유형이 다른 사업부에서 반복되지 않도록 합니다.
  • 현업 출신 감사의 강점 — 사례의 업무 맥락을 이해하고, 현장 언어로 전달합니다.

CASE 03 · 구매·PI·데이터

구매를 개인의 경험에서,
데이터가 남는 구조로

130억 규모 차세대 시스템, 구매 영역 PM — 견적·입찰·계약·평가를 하나의 데이터 흐름으로

01배경 — 문제

입찰 데이터가 쌓이기만 하고, 분석에 쓰이지 못하고 있었습니다.

  • 데이터 분산 — 구매 데이터가 개인 PC·엑셀에 흩어져 조직의 자산이 되지 못함
  • 프로세스 분리 — 견적·입찰·계약·평가가 따로 관리되어 전체 흐름을 보기 어려움
  • 수작업 통제 — 업체 신용·면허 확인, 담합 징후 점검이 사후·수작업에 의존
  • 감사 추적성 부족 — 왜 이 업체를 선택했는지, 어떤 단가로 계약했는지 이력이 남지 않음

02접근 — 어떻게

  • 입찰 시스템 — 입찰 데이터를 DB로 분석할 수 있는 구조로 설계했습니다.
  • Cost DB — 예가 산정 시 입찰 실적과 Cost DB를 함께 조회할 수 있게 했습니다.
  • 재무 연계 — 매출 전표와 매입 전표를 연결해, 실제 거래별 마진을 확인할 수 있게 했습니다.
  • 업체 조회 — 협력사 조회 메뉴에서 신용정보를 자동으로 표시했습니다.
  • 담합 탐지 — IP 중복 점검·투찰율 분석 기능을 구현했고, 실제 점검에서 담합 징후를 포착했습니다.
  • 리딩 — 15명 프로젝트 팀을 리딩하고, 변화관리·사용자 교육을 함께 수행했습니다.

03결과 — 숫자로

130억 원 규모 차세대 시스템 · 구매 영역 PM
25% 단축 구매 업무 처리시간
85% 사용자 만족도 · 15명 팀 리딩

04이 사례가 보여주는 것

  • 구매를 데이터·통제의 구조로 — 개인의 협상력이 아니라, 데이터가 남고 분석되는 구조를 만들었습니다.
  • 감사로 이어지는 설계 경험 — 시스템 통제의 약한 지점을 설계 단계에서 이해합니다.
  • 현업 출신 감사의 차별점 — 통제를 만들어 본 사람이 통제의 빈틈을 압니다.

CASE 04 · 전략·기획

전략을 서비스로,
서비스를 매출로

2021–2022 전략기획 — 해외 유사 선도 기업 벤치마킹 → 실제 전략 반영 → 프롭테크·모바일 서비스 출시, 누적 매출 50억 원

01배경 — 문제

전략이 문서로 끝나면 조직은 움직이지 않습니다.

  • 시야의 한계 — 국내 시장 중심의 시각만으로는 새로운 성장 경로를 찾기 어려움
  • 실행의 간극 — 전략과 현장의 서비스·KPI가 따로 움직이면 성과로 이어지기 어려움
  • 벤치마킹 필요 — 해외 유사 선도 기업의 서비스 모델을 비교·분석해 실제 전략에 반영할 필요

02접근 — 어떻게

  • 해외 벤치마킹 — 서비스 모델·수익 구조·고객 접점 비교
  • 전략 반영 — 벤치마킹 결과를 중장기 전략과 신규 서비스 과제로 구체화
  • 서비스 출시 — 프롭테크, 모바일 서비스
  • 실행 연결 — KPI 관리, 경영진 의사결정 지원, Bain & Company PMO

03결과 — 숫자로

누적 50억 원 신규 서비스 매출
프롭테크 서비스 출시
모바일 서비스 출시

04이 사례가 보여주는 것

  • 전략은 보고서가 아니라 서비스와 매출로 증명 — 벤치마킹을 실제 서비스 출시와 매출로 연결했습니다.
  • 해외 벤치마킹을 실제 전략에 반영하는 실행력 — 비교·분석에서 끝내지 않고, 회사의 전략 과제로 구체화했습니다.
  • 경영진 언어와 현장 실행을 연결 — 전략·KPI·서비스가 같은 방향을 보도록 정리했습니다.

CASE 05 · 자동화·데이터

100% 수작업을 자동화로,
건당 5분을 3분으로

거래업체 재무·주주·거래처 정보 수집을 자체 개발 시스템으로 전환하고, 운영 중 외부 제약도 직접 풀어 성과를 지속시킨 사례

01배경 — 문제

진단·감사에 필요한 거래업체 신용 정보가 전량 수작업이었습니다.

  • 수집 항목 — 거래업체 재무정보, 주주·지분구조, 거래처 비중 정보를 건별로 조회
  • 수집 방식 — 정보 사이트 조회 → 화면 확인 → 수기 정리. 건당 5분 소요
  • 구조적 문제 — 반복 노동과 오류 여지가 상존하고, 담당자의 분석 시간을 잠식
  • 개선 출발 — 생산성 개선 후보 5개 과제 중 '신용평가 정보 추출 자동화'를 선정, 목표는 건당 소요시간 15% 이상 단축

02접근 — 어떻게

03결과 — 숫자로

5분 → 3분 건당 소요시간 · 정보 수집
40% 단축 목표(15% 이상)를 초과한 결과
100% 자동화 수작업 프로세스 전환 · 수집 DB화

04이 사례가 보여주는 것

  • 검증 범위의 확대 — 반복 수집·비교를 시스템에 맡기고, 사람은 이상징후 해석에 집중합니다. 자동화의 본질은 절감이 아니라 검증 범위의 확대입니다.
  • 접근의 확장 — 같은 접근을 거래처 이상징후 자동 탐지 로직으로 발전시켰습니다.
  • 결과의 지속성 — 운영 중 외부 데이터 제약은 기다리지 않고 우회 로직을 직접 재개발해 해소했습니다.
